# wsl 소개

wsl(windows subsystem for linux)은 windows에서 리눅스 배포판을 네이티브에 가깝게 실행할 수 있게 해 주는 microsoft의 기능입니다. 개발자는 리눅스용 패키지 매니저, 빌드 도구, 셸 등을 그대로 사용하면서 windows의 ide와 브라우저 같은 ui 도구를 함께 활용할 수 있습니다. wsl2는 경량 가상 머신 기반으로 더 나은 호환성 및 파일시스템/네트워크 성능을 제공합니다.

windows 10에서도 wsl을 사용할 수 있으나, 일부 기능이나 성능에서 제약이 있을 수 있습니다.

# windows 11 + wsl2(ubuntu) 설치/설정 가이드

## 1) 목표와 팀 표준 원칙

- windows는 **ui(ide, 브라우저, 터미널)** 용도
- wsl ubuntu는 **실행/빌드/테스트(리눅스)** 용도
- 웹/서버 포트는 **wsl에서 띄우면 windows에서 `localhost:포트`로 동일 접속**되게 설정(= localhost forwarding) ([microsoft learn](https://learn.microsoft.com/en-us/windows/wsl/wsl-config))
## 2) wsl2 + ubuntu 설치 (가장 쉬운 방법)

> 아래는 microsoft 공식 설치 흐름입니다. (microsoft learn)
> 
1. **powershell(관리자 권한)** 실행
2. 아래 명령 실행(예: ubuntu 24.04):

```powershell
wsl --install -d ubuntu-24.04
```

1. 설치가 끝나면 **재부팅**
2. 재부팅 후 ubuntu를 실행하면 **리눅스 사용자/비밀번호 생성** 화면이 나옵니다.

설치 확인:

```powershell
wsl --list --verbose
```

여기서 ubuntu가 **version 2**로 보이면 정상입니다. ([microsoft learn](https://learn.microsoft.com/en-us/windows/wsl/install?utm_source=chatgpt.com))
## 3) wsl 업데이트 & 기본 설정(권장)

wsl은 스토어 기반 업데이트가 자주 이뤄지므로, 팀 표준으로 아래를 권장합니다. ([microsoft learn](https://learn.microsoft.com/ko-kr/windows/wsl/install?utm_source=chatgpt.com))

```powershell
wsl --update
wsl --version
```

기본 wsl 버전을 2로 고정(혹시라도 대비):

```powershell
wsl --set-default-version 2
```

## 4) ubuntu 초기 세팅(필수)

ubuntu에서:

```bash
sudo apt update && sudo apt upgrade -y
```

(선택) 서비스 관리가 필요하면 systemd를 켭니다. ([microsoft learn](https://learn.microsoft.com/en-us/windows/wsl/wsl-config))

ubuntu에서 `/etc/wsl.conf`에 아래를 넣고:

```
[boot]
systemd=true
```

windows에서 wsl 재시작:

```powershell
wsl --shutdown
```

## 5) “여러 ubuntu 환경”을 프로젝트별로 쓰는 방법 (권장 운영 방식)

팀이 정말 단순해지려면 **프로젝트별 wsl을 “복제(템플릿)”**하는 방식이 좋습니다.

### 옵션 a) 가장 단순: ubuntu 1개만 쓰고 프로젝트 폴더로 분리

- `~/projects/a`, `~/projects/b` 식으로만 나눔
- 가장 관리가 쉽지만, 런타임 충돌이 잦으면 불편해질 수 있음

### 옵션 b) 팀 표준 추천: “베이스 ubuntu → export/import로 프로젝트별 배포판 만들기”

1. 베이스 배포판(예: ubuntu-24.04)을 준비한 뒤(업데이트까지 끝난 상태)
2. windows에서 export:

```powershell
wsl --export ubuntu-24.04 c:\\wsl\\ubuntu-base.tar
```

3. 프로젝트별로 import (이름을 다르게):

```powershell
wsl --import ubuntu-a c:\\wsl\\ubuntu-a c:\\wsl\\ubuntu-base.tar --version 2
wsl --import ubuntu-b c:\\wsl\\ubuntu-b c:\\wsl\\ubuntu-base.tar --version 2
```

4. 실행:

```powershell
wsl -d ubuntu-a
```

이 방식은 “a는 next+python, b는 react+java”처럼 **환경을 확실히 분리**할 때 특히 좋습니다.


## 6) windows ide에서 wsl ubuntu에 붙는 기본 사용법(팀 공통)

ide 종류가 무엇이든(예: vs code류, windsurf/antigravity 등) 팀 표준은 이 한 줄로 통일하시면 편합니다:

- **코드는 wsl 리눅스 홈(`~`) 아래에 둔다**
- ide는 **wsl 배포판의 폴더를 열어서** 작업한다

ubuntu에서 프로젝트 폴더로 이동 후(예: `~/projects/a`) 다음처럼 ide 명령을 실행하거나(ide별 방식에 맞게) “wsl에서 폴더 열기” 기능을 씁니다.

> 핵심은 “windows에서 편집하되 실행은 wsl에서”가 자동으로 되게 만드는 겁니다.
> 


## 7) (중요) wsl에서 띄운 포트를 windows에서 `localhost`로 접속하기

### 7-1) 기본 원리(대부분 자동으로 됨)

wsl2는 기본적으로 **localhost forwarding**이 켜져 있으면, wsl에서 열어둔 포트를 windows에서 **`http://localhost:포트`**로 접근할 수 있게 해줍니다.

이 동작은 `.wslconfig`의 `localhostforwarding=true` 설정으로 제어됩니다. ([microsoft learn](https://learn.microsoft.com/en-us/windows/wsl/wsl-config))

### 7-2) 동작 확인(가장 쉬운 테스트)

ubuntu에서:

```bash
python3 -m http.server 8000 --bind 0.0.0.0
```

windows 브라우저에서 접속:

- `http://localhost:8000`

정상입니다.

### 7-3) 프레임워크별 권장 “바인드 주소”

windows에서만 접속할 거면 보통 문제가 없지만, 팀에서 혼선을 줄이려면 개발 서버는 가능하면 **`0.0.0.0`로 바인드**를 표준으로 두는 게 좋습니다.

- next.js 예시:

```bash
next dev -h 0.0.0.0 -p 3000
```

- vite 예시:

```bash
vite --host 0.0.0.0 --port 5173
```

- fastapi(uvicorn) 예시:

```bash
uvicorn app:app --host 0.0.0.0 --port 8000
```

### 7-4) “windows에서 localhost 접속이 안 될 때” 체크리스트

1. `.wslconfig`에 `localhostforwarding=true`가 꺼져 있지 않은지 확인 ([microsoft learn](https://learn.microsoft.com/en-us/windows/wsl/wsl-config))
2. wsl 전체 재시작:

```powershell
wsl --shutdown
```

1. 포트가 windows에서 이미 사용 중이면 충돌 날 수 있습니다(특히 80/443). 다른 포트로 테스트하세요.

### `.wslconfig` 최소 예시(권장)

`%userprofile%\\.wslconfig` (예: `c:\\users\\사용자\\.wslconfig`)에:

```
[wsl2]
localhostforwarding=true
```

설정 변경 후에는 wsl을 재시작해야 반영됩니다. ([microsoft learn](https://learn.microsoft.com/en-us/windows/wsl/wsl-config))


## 8) lan에서 wsl에 직접 접속까지 필요하면: mirrored networking

“windows에서 localhost로 접속”만 필요하면 여기까지는 보통 불필요합니다.

다만 **같은 네트워크의 다른 pc/모바일에서 wsl로 바로 접속**해야 하는 요구가 있으면, `networkingmode=mirrored`가 선택지입니다. ([microsoft learn](https://learn.microsoft.com/en-us/windows/wsl/networking))

단, 미러 모드는 환경에 따라 이슈가 보고된 적도 있으니(조직 표준 도입 전 poc 권장) 신중히 적용하는 게 안전합니다. ([github](https://github.com/microsoft/wsl/issues/11002?utm_source=chatgpt.com))

# 부록(옵션): wsl2 + zsh quickstart kit 설치 가이드

> 아래 부록은 “선택 사항”입니다. 팀 표준 쉘/프롬프트를 통일하고 싶은 경우에만 적용하세요.
> 

## 1. 필수 패키지 설치 (기반 공사)

```bash
sudo apt update && sudo apt install zsh git keychain -y
```

## 2. 키트 설치 및 설정 연결 (wsl 최적화)

```bash
# 1. 홈 디렉터리로 이동 및 클론
cd ~
git clone https://github.com/unixorn/zsh-quickstart-kit.git .zsh-quickstart-kit

# 2. 기존 설정 백업 (안전장치)
[ -f ~/.zshrc ] && mv ~/.zshrc ~/.zshrc.bak
[ -f ~/.p10k.zsh ] && mv ~/.p10k.zsh ~/.p10k.zsh.bak

# 3. 핵심 설정 파일 심볼릭 링크 연결 (강제 적용)
ln -sf ~/.zsh-quickstart-kit/zsh/.zshrc ~/.zshrc
ln -sf ~/.zsh-quickstart-kit/zsh/.p10k.zsh ~/.p10k.zsh
```

## 3. 쉘 변경 및 p10k 테마 설정

```bash
# 1. 기본 쉘 변경
chsh -s $(which zsh)

# 2. zsh 실행 (설정 로드)
exec zsh

# 3. p10k 설정 마법사 실행 (화면 지시에 따라 y/n 및 스타일 선택)
p10k configure
```

## 4. 경고 메시지 제거 (ssh key listing 끄기)

```bash
zqs disable-ssh-key-listing
```

## 5. [중요] `ls` 명령어 업그레이드 (eza 적용)

1. 파일 열기:

```bash
nano ~/.zshrc
```

2. **맨 마지막 줄**에 아래 내용을 붙여넣기:

```bash
# --- eza(ls 대체) 설정 ---
# 기존의 ll (ls -lfa | less) 알리아스를 덮어쓰고 색상/아이콘 강제 적용
if command -v eza >/dev/null; then
	alias ls="eza --group-directories-first --icons"
	alias ll="eza -l -a --icons --group-directories-first --time-style=long-iso"
	alias l="eza -l -a --icons --group-directories-first --time-style=long-iso --git"
	alias tree="eza --tree --icons"
fi
```

3. 저장/종료 후 적용:

```bash
source ~/.zshrc
```

> 참고: eza가 설치되어 있어야 적용됩니다. (없으면 위 블록은 자동으로 무시됩니다.)

## 💡 [필수] windows terminal 폰트 설정

이 과정을 건너뛰면 아이콘이 `□`처럼 깨져 보일 수 있습니다.

1. windows에 **meslolgs nf** 폰트를 설치
2. windows terminal 설정에서 ubuntu 프로필 → 모양(appearance) → 글꼴(font face)을 `meslolgs nf`로 지정
3. 색상 자동 보정 비활성화(프롬프트 색이 흐려지는 문제 방지)

`settings.json`의 ubuntu 프로필에 아래를 추가/수정:

```json
{
	"name": "ubuntu 24.04",
	"source": "windows.terminal.wsl",
	"font": { "face": "meslolgs nf" },
	"adjustindistinguishablecolors": "never"
}
```
