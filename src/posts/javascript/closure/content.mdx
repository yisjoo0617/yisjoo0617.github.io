자바스크립트를 공부하다 보면 가장 어렵게 느껴지는 벽 중 하나가 바로 **클로저(Closure)**입니다. 하지만 클로저는 자바스크립트의 강력한 기능 중 하나로, 이를 이해하면 코드의 캡슐화나 상태 유지 등을 훨씬 쉽게 처리할 수 있습니다.

이번 포스팅에서는 클로저가 무엇인지, 그리고 실무에서 어떻게 활용되는지 자세히 알아보겠습니다.

## 1. 클로저란?

MDN에서는 클로저를 다음과 같이 정의합니다.
> "클로저는 함수와 그 함수가 선언된 렉시컬 환경(Lexical Environment)의 조합입니다."

말이 조금 어렵죠? 쉽게 풀어서 설명하면, **"외부 함수의 실행이 끝났음에도 불구하고, 내부 함수가 외부 함수의 변수에 접근할 수 있는 메커니즘"**을 말합니다.

이를 이해하기 위해서는 먼저 **렉시컬 스코프(Lexical Scope)**에 대해 알아야 합니다.

## 2. 렉시컬 스코프 (Lexical Scope)

자바스크립트 엔진은 함수를 어디서 호출했는가가 아니라, **어디서 정의했는지**에 따라 상위 스코프를 결정합니다. 이를 렉시컬 스코프(정적 스코프)라고 합니다.

아래 예시 코드를 통해 동작을 확인해 보겠습니다.

```javascript
const x = 1;

function outer() {
  const x = 10;
  inner();
}

function inner() {
  console.log(x); // 결과는 무엇일까요?
}

outer();
```

코드 실행 결과는 1이 출력됩니다. inner 함수가 outer 내부에서 호출되었지만, 정의는 전역에서 되었기 때문에 전역 변수인 x를 참조하는 것이죠.

## 3. 클로저의 동작 원리

그렇다면 이제 본격적으로 클로저가 발생하는 상황을 살펴보겠습니다.

```javascript
function outer() {
  const message = 'Hello, Closure!';
  
  return function inner() {
    console.log(message);
  };
}

const myFunc = outer(); // outer 함수의 실행이 끝났습니다.
myFunc(); // 그런데 'Hello, Closure!'가 출력됩니다.
```

보통의 함수라면 outer() 실행이 끝난 후 message 변수는 가비지 컬렉션의 대상이 되어 사라져야 합니다. 하지만 inner 함수가 반환되면서 message 변수를 여전히 참조하고 있기 때문에, 자바스크립트 엔진은 이 메모리를 유지합니다. 이것이 바로 **클로저**입니다.

## 4. 클로저 활용하기

클로저는 단순히 현상을 이해하는 것을 넘어, 실무에서 특정 목적으로 자주 사용됩니다.

### 1) 정보 은닉 (Encapsulation)
자바스크립트에는 완벽한 private 접근 제한자가 없었을 때(최근에는 # 문법이 생겼지만), 클로저를 통해 외부에서 접근할 수 없는 변수를 만들었습니다.

```javascript
function createCounter() {
  let count = 0; // 외부에서 직접 수정할 수 없는 변수

  return {
    increase: function() {
      count++;
      return count;
    },
    decrease: function() {
      count--;
      return count;
    }
  };
}

const counter = createCounter();

console.log(counter.increase()); // 1
console.log(counter.increase()); // 2
console.log(counter.count); // undefined (외부 접근 불가)
```
이처럼 count 변수는 increase, decrease 함수를 통해서만 조작할 수 있습니다. 상태를 안전하게 보호할 수 있죠.

### 2) 상태 유지
현재 상태를 기억하고 다음에 사용할 때 그 상태를 이어받는 로직에 유용합니다.

```javascript
function multiplier(factor) {
  return function(number) {
    return number * factor;
  };
}

const double = multiplier(2);
const triple = multiplier(3);

console.log(double(5)); // 10
console.log(triple(5)); // 15
```
double 함수는 factor가 2인 환경을 기억하고 있고, triple 함수는 3인 환경을 기억하고 있습니다.

## 5. 주의할 점: 메모리 누수?

클로저는 참조하는 외부 변수를 메모리에 계속 유지하기 때문에, 무분별하게 사용하면 메모리 소비가 늘어날 수 있습니다. 하지만 현대 브라우저의 엔진은 최적화가 잘 되어 있어, 실제로 사용되지 않는 변수는 알아서 제거하기도 합니다. 다만, 필요 없어진 클로저는 null 등을 할당해 참조를 끊어주는 습관이 좋겠죠.

## 마무리

클로저는 처음에는 낯설지만, **"함수가 태어난 곳을 기억하는 것"**이라고 생각하면 이해하기 쉽습니다. 이 개념을 익히면 리액트의 useState 훅이나 다양한 라이브러리의 내부 동작을 이해하는 데 큰 도움이 됩니다.
